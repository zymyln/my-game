# AGENTS.md

本仓库只开发《循环小镇》。使用 GitHub 在主力机与其他电脑之间同步，保持代码、剧本与素材的工作边界。

## 电脑分工

- **主力机**：负责所有程序开发、调试、测试、依赖管理、地图运行数据、素材/文本接入与发行。可以为开发和接入修改相关文本、素材与文档。
- **其他电脑**：只能制作和整理素材、修改企划与剧本文本、编写非程序文档；不得修改程序、工具脚本、运行配置或依赖。需要程序配合时记录需求，交主力机处理。
- 会话先依据用户说明确认当前机器角色；新机器角色不明确时先进行只读检查并确认，不能自行当作主力机。

## 内容边界

- `src/`、`tools/`、`index.html`、启动脚本、包配置及锁文件：仅主力机修改。
- 程序生成器、构建/校验脚本、碰撞数据、事件触发/场景编排、运行配置：即使位于 `docs/`、`assets/` 或以 JSON 保存，也仅主力机修改。
- `content/` 的企划、对白、独白、选项文案，`assets/` 的图片/音频/原始工程及来源记录，非程序文档：其他电脑可以修改。不得借修改“文本文件”更改事件 ID、执行逻辑或数据接口。
- 其他电脑可以制作地图像素素材、布局草图与地图编辑工程；涉及运行碰撞、触发器或脚本的混合文件，先提供美术/布局副本，由主力机合并接入。
- 素材原稿与处理稿分开保存，注明来源、用途及是否定稿。未接入素材不能宣称已在游戏中使用。
- 不自动修改 `AGENTS.md`、`.gitignore` 或已确认的公共接口约定；用户明确要求修改时，按本次授权范围处理。

## 会话开始

1. 查看工作区状态，执行 `git pull`；遇到冲突保留各方改动，不用强制覆盖解决。
2. 读取 `docs/state.md` 最近三条、`docs/交接.md` 及本轮相关文档。状态不足三条时读取全部。
3. 已建立的公共文本/素材接口说明需一并阅读；接口尚未确定时不套用其他游戏格式。

## 会话结束

1. 查看差异，确认只包含本轮授权内容及当前机器可修改的文件。
2. 在 `docs/state.md` 追加完成内容、验证结果、待定项与下一步，避免写入密钥或机器隐私。
3. 执行 `git add .`、`git commit -m "简短说明"`、`git push`。先检查再 add，不能把他人的未完成改动一并提交。
4. 确认推送结果再报告完成；若本轮只读且无改动，不创建空提交。

## 约束

- 不写入 API Key 或密码；密钥仅放本地 `.env`，不得入库。
- 不擅自安装新依赖或全局工具。恢复现有锁文件依赖按项目说明执行，不借机升级。
- 一次只完成一个可验证事项，做完等用户检查。
- 正式企划、待定问题和地图候选分开标明，不把助手提案直接当作设定。
- 当前项目与《瓶中的幸福》独立，不自动搬入其代码、剧本、契约或全套素材。
