## 新协作规则要点

主力机负责程序和运行接入；其他电脑仅做素材、文本与非程序文档。**文件后缀或所在目录不决定权限**：碰撞/事件 JSON、HTML、CSS、锁文件和 docs 中的 `.mjs` 生成器仍是程序。其他电脑发现程序问题，写明需求交主力机处理。

本次新规则不禁止主力机为了开发和接入修改文本或素材；“其他电脑只能制作素材、改文本等”仍然有效。旧仓库规则在正式迁出前继续适用，不在旧仓库直接覆盖 AGENTS 或 .gitignore。

## 用户建好新仓库后的执行顺序

1. 确认新仓库地址与主力机本地目录，查看新仓库已有文件，按 manifest 复制明确文件；不覆盖已有用户改动。
2. 应用新文档草案并修正上述迁移引用，新 `.gitignore` 至少排除 `node_modules/`、`.env`、`.env.*`（如需要 `.env.example`，仅放无密钥模板并设例外）、日志和本地缓存。此准备阶段未创建该文件。
3. 新仓库尚无提交时不要求先 pull；按远端实际状态初始化或克隆，不覆盖已有 README/历史。以普通首次提交引入当前快照，旧仓库保留历史，不自动重写历史。
4. 在新目录按现有锁文件恢复依赖。先检查 `node --check src/main.js`、`node --check tools/dev.mjs`，再启动本机服务，核对页面/Phaser 加载、行走、碰撞、对白与失焦停止，并打开两张当前地图。
5. 补记来源提交与迁移后验证结果，再向新远端提交推送。之后其他电脑从新仓库克隆并读取新规则，不再对旧路径提交循环小镇更改。
6. 主力机与至少一台其他电脑验证同步后，才由用户决定旧仓库是否清理重复文件。本轮不删除、不移动原文件，也不自动发布网站。

准备清单只保证所列当前文件来源可追踪，不等于新仓库已建立、图片已备齐或迁移验收已完成。
