# contract.md

两边都只读。要改必须先问。

## 数据源

`content/script/chN.md` 是剧本的唯一真源，程序直接读取，不需要转成 JSON。文本机改完台词，刷新页面即生效。

`content/dialogue.json` 只留给独立的样例对话（目前是自由漫游里 SH-04 的二十二条）。它的字段和 ID 规则见下，但不要再往里面塞整章剧情数据。

## 剧本里程序认得的写法

| 写法 | 含义 |
|---|---|
| `## SC-xx 场景名` | 场景。当前 SC-01 到 SC-04 各自绑定一张地图 |
| `### SH-xx 镜头名` | 镜头。增删镜头或改编号必须同步程序端的剧情编排 |
| `角色[表情标注]：台词` | 说话。标注必须在上方表情表里登记。伊蕾娜是「姿势·表情」，其他角色只有一个表情 |
| `角色[表情标注]（心）：台词` | 内心话，按旁白呈现 |
| `旁白：台词` | 旁白，不显示说话人立绘 |
| `【演出】` | 给程序的镜头提示。程序会跳过这些行，可以自由改写 |
| `- 光粒子①：文字` | 六片幸福。SH-12 必须正好六条 |
| `- 物品名：旁白：文字` | 可点击调查，玩家点开才显示 |

## 立绘与背景命名

都用文件名，不含扩展名。**文件名一律小写，第一个下划线之前是角色。**

- 立绘：`角色_姿势`，需要差分的姿势再接上表情。例如 `elaina_standing`、`elaina_standing_smile`、`elaina_thinking`、`elaina_confident`、`emil_bright`、`nino_teary`、`chief_calm`。只有一张脸的姿势，名字到姿势为止。完整对照表见 `content/script/ch1.md` 的表情表。
- 背景：`field_day`、`hall`、`gate_dusk`、`field_dusk`。
- 图片放 `assets/` 下，PNG。登记由程序端在 `assets/manifest.json` 里做。
- 程序端靠第一个下划线之前那段判断角色（左右立绘、缺图回退都用它），所以角色名不要改大小写，也不要换写法。

## dialogue.json 字段

| 字段 | 含义 |
|---|---|
| `speaker` | 说话人名字。旁白填 `旁白` |
| `text` | 台词正文 |
| `face` | 立绘文件名，不含扩展名。旁白填 `null` |
| `bg` | 背景图文件名 |
| `next` | 下一句的 ID，最后一句填 `null` |

## 对话 ID 规则

格式：`ch编号_场景_序号`，例如 `ch1_cave_01`。

ID 一旦建立，永不修改和删除。

只用于 `dialogue.json`。程序内部播放游标不是对外 ID，不写回仓库。
